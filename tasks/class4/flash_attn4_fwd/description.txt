# Task: flash_attn4_fwd (Class 4 — Unsolved)

Implement FlashAttention-4 forward pass using CUDA/PTX code for NVIDIA
Blackwell (SM100) GPUs, WITHOUT using CuTe DSL. CUTLASS C++ headers are allowed.

## Background

FlashAttention-4 (Dao et al., 2025) achieves 1613 TFLOPS (71% utilization) on B200
GPUs by co-designing algorithms and kernel pipelines for Blackwell's asymmetric
hardware scaling. The official implementation uses CuTe DSL (a Python-embedded GPU
programming framework). No hand-written CUDA implementation exists.

## Challenge

Write a pure CUDA/PTX kernel implementing FA4's forward pass. This requires:

### 1. Conditional Softmax Rescaling
Standard FlashAttention rescales the running output O every tile. FA4 only
rescales when the new row-max exceeds the old by a threshold τ = log₂(256) = 8.0,
skipping ~90% of rescaling operations. The final normalization corrects any
intermediate drift.

### 2. Software Exponential Emulation
Blackwell's MUFU.EX2 unit is a throughput bottleneck (shared with tensor cores).
FA4 uses a degree-3 polynomial approximation of 2^x on FMA units for the
majority of softmax entries, reserving hardware exp2 only for the ~10-25% of
entries that need higher precision. Max relative error: 8.8×10⁻⁵ at FP32.

### 3. Warp-Specialized Pipelining
Five distinct warp roles execute concurrently:
- **Load warps**: TMA bulk copies (Q/K/V → shared memory)
- **MMA warps**: Tensor core WGMMA (S = Q·Kᵀ, O = P·V) via tcgen05.mma
- **Softmax warps**: Online softmax with conditional rescaling
- **Correction warps**: Output rescaling via tensor memory (TMEM)
- **Epilogue warps**: TMA store (O → global memory)

### 4. Blackwell-Specific Hardware Features
- **Tensor Memory (TMEM)**: 256KB programmer-managed L1 for accumulators
- **tcgen05.mma**: Fully asynchronous 128×128 MMA with TMEM output
- **TMA**: Tensor Memory Accelerator for bulk async transfers
- **2-CTA MMA mode**: Paired CTAs sharing MMA resources

## Function Signature

`solution.cu` is compiled as a PyTorch C++/CUDA extension (`TORCH_EXTENSION_NAME`) and must
define the following function and export it with pybind11 under the same name:

```c++
#include <torch/extension.h>

torch::Tensor flash_attn4_fwd(
    torch::Tensor Q,    // [batch, seqlen_q, num_heads, head_dim] BF16
    torch::Tensor K,    // [batch, seqlen_k, num_heads_k, head_dim] BF16
    torch::Tensor V,    // [batch, seqlen_k, num_heads_k, head_dim] BF16
    bool is_causal
);   // returns O with the shape and dtype of Q

PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    m.def("flash_attn4_fwd", &flash_attn4_fwd, "FlashAttention-4 Forward (CUDA)");
}
```

## Supported Configurations

- **Precision**: BF16
- **Head dimensions**: 64, 128, 256
- **Sequence lengths**: 1K, 4K, 8K, 16K, 32K
- **Causal / non-causal**
- **GQA**: num_heads_k may differ from num_heads

## Metrics

- **Correctness**: |O_custom - O_ref| < atol=1e-2, rtol=1e-2 (BF16 precision)
- **Performance**: TFLOPS achieved vs. FA4 CuTe DSL baseline

- **CUDA**: 13.0+

## Why Class 4

This task is classified as "unsolved" because:
1. No hand-written CUDA implementation of FA4 exists — only CuTe DSL
2. Even the Triton team abandoned writing Blackwell attention kernels
3. Requires deep understanding of Blackwell's async MMA, TMEM, TMA, and 2-CTA mode
4. Correct warp specialization scheduling is extremely difficult without CuTe's abstractions
