# Task: 77_blackwell_fmha

## Target Hardware
NVIDIA B200 (Blackwell, SM100 / `sm_100a`). The task is built with `-gencode arch=compute_100a,code=sm_100a` and is skipped on other GPUs.

Fused multi-head attention forward pass (prefill) with grouped-query attention (GQA), optional causal mask, and a log-sum-exp (LSE) output, compared against cuDNN's scaled-dot-product attention.

## Function Signature

Implement BOTH overloads in `solution.h` (one per dtype; they may share a template):

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_fp16.h>
#include <cuda_bf16.h>

cudaError_t BlackwellFmha(
    int batch, int num_q_heads, int num_kv_heads, int seq_q, int seq_k, int head_dim,
    bool causal,
    __half const *Q, __half const *K, __half const *V,
    __half *O, float *LSE);

cudaError_t BlackwellFmha(
    int batch, int num_q_heads, int num_kv_heads, int seq_q, int seq_k, int head_dim,
    bool causal,
    __nv_bfloat16 const *Q, __nv_bfloat16 const *K, __nv_bfloat16 const *V,
    __nv_bfloat16 *O, float *LSE);
```

## Operation

For every batch b and query head h, with kv(h) = h / (num_q_heads / num_kv_heads) (consecutive query heads share a KV head) and scale = 1 / sqrt(head_dim):

    S[i, j]   = scale * dot(Q[b, i, h, :], K[b, j, kv(h), :])       (i < seq_q, j < seq_k)
    S[i, j]   = -inf for j > i when causal                           (causal tests have seq_q == seq_k)
    P[i, :]   = softmax(S[i, :])
    O[b, i, h, :]  = sum_j P[i, j] * V[b, j, kv(h), :]
    LSE[b, h, i]   = log(sum_j exp(S[i, j]))                         (natural log, FP32)

The causal mask is aligned to the top-left (key j is visible to query i iff j <= i).

## Data Types and Precision

Q, K, V, O are FP16 or BF16 (per overload). LSE is FP32. Both GEMMs (Q K^T and P V) must be accumulated in FP32 and the softmax must be computed in FP32 (the probabilities may be rounded to the 16-bit input type before the P V product, as flash-attention kernels do). Lower-precision arithmetic (FP8, FP6, FP4, INT8 operands, FP16 accumulation, including tensor-core paths that use them) is not allowed even if it passed the tolerance.

## Memory Layout (all row-major, contiguous, 256-byte aligned device pointers)

- Q, O: `[batch, seq_q, num_q_heads, head_dim]`, element (b, i, h, d) at `((b * seq_q + i) * num_q_heads + h) * head_dim + d`.
- K, V: `[batch, seq_k, num_kv_heads, head_dim]`, element (b, j, g, d) at `((b * seq_k + j) * num_kv_heads + g) * head_dim + d`.
- LSE: `[batch, num_q_heads, seq_q]` FP32, element (b, h, i) at `(b * num_q_heads + h) * seq_q + i`.

`head_dim` is 128 in all tests. O and LSE hold NaN on entry; every element must be written.

## Correctness

The reference and your function read the same inputs and write to separate O / LSE buffers that are pre-filled with NaN. After your function returns, **every** element of O and of LSE is compared with the reference:

- every element must be finite (NaN / Inf fail, so unwritten elements fail);
- `|x - ref| <= max_rms * RMS(ref) + rel * |ref|` for every element, and the relative Frobenius error `||x - ref|| / ||ref|| <= fro`.

| quantity   | max_rms | rel    | fro  |
|------------|---------|--------|------|
| O, BF16    | 6e-2    | 2.4e-2 | 7.5e-3 |
| O, FP16    | 1.2e-2  | 4.5e-3 | 1e-3 |
| LSE (FP32) | 5e-5    | 5e-5   | 2e-5 |

**The inputs change on every call.** Q, K and V are all regenerated with a new seed before every timed call of the reference and of your function (outside the timed region); the first correctness check and the final re-check use their own seeds, and the final re-check runs on fresh inputs for every case, with the reference recomputed and your outputs re-poisoned. Outputs and input-dependent intermediates must therefore be recomputed on every call; caching results across calls produces wrong answers.

## Performance

For each case the harness times the reference and your function with CUDA events (the L2 cache is flushed before every trial; O and LSE are re-poisoned outside the timed region) and reports `Ref time`, `Kernel time` and `Speedup = ref_min / kernel_min`. The score is the geometric mean of the speedups over the five cases. Your function is timed as a whole call, including host-side launch setup. One-time setup (e.g. `cudaFuncSetAttribute`, tensor-map creation) may be cached in function-local statics.

## Rules

- Solutions must be your own kernels: no cuBLAS / cuDNN (the reference itself is cuDNN, so any use of cuDNN / cudnn-frontend is rejected), no CUTLASS device / kernel / collective templates. CuTe and low-level building blocks (barriers, pipelines, layouts, `tcgen05` PTX) are allowed.
- seq_q == seq_k in every test.
