# Task: 84_blackwell_narrow_precision_sparse_gemm

## Target Hardware
NVIDIA B200 (Blackwell, SM100 / `sm_100a`). The task is built with `-gencode arch=compute_100a,code=sm_100a` and is skipped on other GPUs.

Structured-sparse NVFP4 x dense NVFP4 -> BF16 block-scaled GEMM, compared against a CUTLASS-based reference.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cstdint>
#include <cuda_runtime.h>
#include <cuda_bf16.h>

cudaError_t BlackwellNvfp4SparseGemm(
    int M, int N, int K,
    float alpha,                       // product of the two per-tensor (global) FP32 scales
    uint8_t const *A,   uint8_t const *E, uint8_t const *SFA,   // sparse operand: compressed values, metadata, scales
    uint8_t const *B,   uint8_t const *SFB,                     // dense operand: values, scales
    __nv_bfloat16 *D);
```

## Operation

A is an M x K weight matrix that is **2:4 structured sparse** and stored compressed (values + metadata); B is a dense
K x N activation matrix. Both are NVFP4: FP4 E2M1 values with UE4M3 block scales (plus a per-tensor FP32 global scale
folded into `alpha`).

    D[m, n] = bf16( alpha * sum_k  (a[m,k] * sfa[m, k/32]) * (b[n,k] * sfb[n, k/32]) )

`a[m,k]` is the logical (dense, K-wide) sparse matrix reconstructed from `A` + `E`; pruned elements are exactly zero.
The solution receives **only** the compressed operands (A, E, SFA); it never sees the dense matrix.

## Sparsity pattern (what "2:4" means for FP4 on Blackwell)

The sparse FP4 tensor-core instruction prunes in units of **pairs** of adjacent K elements: pair `p` of a chunk covers
`k = 8c + 2p` and `8c + 2p + 1`. In every aligned chunk of 8 consecutive K elements (`c = k / 8`, i.e. 4 pairs) exactly
**2 of the 4 pairs are kept** (2:4 over pairs, which is 4:8 over elements); the other 2 pairs are zero. Per row, `A`
therefore stores `K / 2` FP4 values.

## Memory Layouts (exact)

`K` is a multiple of 256 for every tested shape (the metadata tile covers 256 K elements). All pointers are device
pointers, 256-byte aligned. Notation: `Mp = roundup(M, 128)`.

**Compressed values `A`**: `uint8_t[M][K/4]` row-major (`lda = K/4` bytes). Byte `j = 2c + s` of row `m` is the `s`-th kept
pair (`s = 0, 1`, in ascending pair position) of chunk `c`: LOW nibble = the pair's element with even `k`, HIGH nibble =
the element with odd `k`. A nibble is an E2M1 code: bit 3 = sign, bits 2:0 = magnitude index into
`{0, 0.5, 1, 1.5, 2, 3, 4, 6}` (code 8 is -0). All 16 codes occur in the test data.

**Metadata `E`**: `uint8_t[(K/256) * Mp * 16]` bytes. For row `m` and 16-element group `g = k / 16` (two chunks of 8)
the byte is at

    offset_E(m, g) = (g / 16) * Mp * 16  +  (m / 128) * 2048  +  (m % 128) * 16  +  (g % 16)

(tiles of 128 rows x 256 K elements = 128 x 16 bytes, row-major inside the tile, tiles ordered row-tile-fastest then along
K; rows >= M inside the last row tile are padding and hold a valid dummy value). The byte holds two 4-bit codes: the LOW
nibble belongs to chunk `2g`, the HIGH nibble to chunk `2g + 1`. A nibble `n` says which pairs of the chunk the two kept
values of `A` are: `idx0 = n & 3` is the pair position (0..3) of kept pair `s = 0`, `idx1 = (n >> 2) & 3` that of kept pair
`s = 1`, always `idx0 < idx1`; the only occurring nibbles are `0x4 0x8 0x9 0xC 0xD 0xE`. Hence

    a[m, 8c + 2*idx_s + h] = decode( (A[m*K/4 + 2c + s] >> (4*h)) & 15 ),   s = 0,1,  h = 0,1;   all other a[m, .] of chunk c are 0.

**Dense operand `B`**: `uint8_t[N][K/2]` (K-contiguous; equivalently column-major [K, N]); byte `j` of row `n` holds
`k = 2j` (low nibble) and `2j + 1` (high nibble), same E2M1 coding.

**Scale factors `SFA`, `SFB`**: one UE4M3 byte per (row, **32** logical K elements) -- the sparse NVFP4 MMA uses 32-element
blocks for both operands (for `A` that is 16 stored values) -- i.e. scale column `c = k / 32`, `Kb = K / 32` columns.
Decoded value of byte `b`: `(1 + (b & 7)/8) * 2^(((b >> 3) & 15) - 7)` for exponent field > 0, `(b & 7) / 512` for
exponent field 0 (bit 7 is 0). Stored in the cuBLAS / CUTLASS "swizzled 128x4" layout: rows padded to a multiple of 128 and
the scale columns to a multiple of 4 (`Kb_pad = roundup(Kb, 4)`); `roundup(rows, 128) * Kb_pad` bytes; the byte of
(row `r`, column `c`) lives at

    offset_SF(r, c) = ( (r / 128) * (Kb_pad / 4) + (c / 4) ) * 512  +  (r % 32) * 16  +  ((r / 32) % 4) * 4  +  (c % 4)

Padding bytes are zero. `SFA` uses `rows = M`, `SFB` uses `rows = N`.

**Output**: `D` is row-major [M, N] BF16 (`ldd = N`), i.e. feature-major (rows = output features, columns = tokens). It
holds NaN on entry; every element must be written.

Equivalently: prune a dense A to the pattern above, then for every chunk store the two kept pairs in position order and
the 4-bit code `idx0 | idx1 << 2`.

## Problem Sizes

The linear layers of Llama-3.1-70B with 2:4-pruned NVFP4 weights on one B200 (hidden 8192, 64 query / 8 KV heads of
dimension 128 -> fused QKV 10240, FFN 28672 -> fused gate+up 57344, vocabulary 128256). The weights are the sparse operand
A (M = output features, K = input features); B holds the N tokens: one decode step of 128 sequences or an 8K-token prefill chunk.

| label            | M      | N    | K     | layer                        |
|------------------|--------|------|-------|------------------------------|
| decode_mlp_up    | 57344  | 128  | 8192  | fused gate+up projection     |
| decode_mlp_down  | 8192   | 128  | 28672 | FFN down projection          |
| decode_lm_head   | 128256 | 128  | 8192  | LM head                      |
| prefill_qkv      | 10240  | 8192 | 8192  | fused QKV projection         |
| prefill_o_proj   | 8192   | 8192 | 8192  | attention output projection  |
| prefill_mlp_up   | 57344  | 8192 | 8192  | fused gate+up projection     |
| prefill_mlp_down | 8192   | 8192 | 28672 | FFN down projection          |

Two extra correctness-only cases (not timed): (M=200, N=1152, K=1280) exercises padded metadata / scale rows, and
(M=1152, N=16, K=2048) a tiny token count. `alpha = 0.00731`. Data: uniformly random FP4 codes, uniformly random valid
metadata nibbles, scales log-uniform in [0.125, 4) rounded to UE4M3 (full 3-bit mantissas).

## Data Types and Precision

FP4 E2M1 values, UE4M3 scales, **FP32 accumulation**, BF16 output (round-to-nearest-even of the FP32 result times
`alpha`). Rounding the dequantized operands to FP8, FP16 / BF16 accumulation, 16-element scale blocks, power-of-two scales
etc. are not allowed even if they pass the tolerance.

## Correctness

The reference (which consumes exactly the buffers you receive) and your solution write to separate buffers that
are pre-filled with NaN. After your function returns, **every** element of D is compared with the reference output:

- every element must be finite (NaN / Inf fail, so unwritten elements fail);
- `|D - ref| <= 1e-3 * RMS(ref) + 0.03125 * |ref|` for every element;
- the relative Frobenius error `||D - ref|| / ||ref||` must be `<= 3e-4`.

**Inputs change on every call.** Before every timed call of both the reference and your function, the harness
regenerates the dense activation operand B and its scale factors SFB with a new random seed (outside the timed region);
the 2:4-sparse weights A with their metadata E and scales SFA stay fixed. The final re-check runs on a fresh input for
every case, with the reference recomputed and D re-poisoned. Outputs and any input-dependent intermediates must therefore
be recomputed on every call; only data derived from the fixed operands may be cached.

## Performance

For each shape the harness times the reference and your function with CUDA events (L2 flushed before every trial,
D re-poisoned outside the timed region) and reports `Ref time`, `Kernel time` and `Speedup = ref_min / kernel_min`. The score
is the geometric mean of the speedups over the seven shapes.

Your function is timed as a whole call, including any host-side launch setup. One-time setup (e.g.
`cudaFuncSetAttribute`, tensor-map creation) may be cached in function-local statics.
