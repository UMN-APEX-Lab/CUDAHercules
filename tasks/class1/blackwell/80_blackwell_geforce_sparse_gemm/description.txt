# Task: 80_blackwell_geforce_sparse_gemm

## Target Hardware

NVIDIA Blackwell GeForce / RTX-class GPU, SM120 / `sm_120a`.

## Goal

Implement the solution-side entrypoint in `solution.h` for the CUTLASS
`80a_blackwell_geforce_mxfp8_bf16_sparse_gemm` harness.

The benchmark compiles:

```bash
make test CUTLASS_DIR=<cutlass>
```

which expands to an `nvcc` build of `80a_blackwell_geforce_mxfp8_bf16_sparse_gemm.cu`
with `-DKH_TEST_SOLUTION` and `-gencode arch=compute_120a,code=sm_120a`.

## Public Entrypoint

The public solution API is the function you must define in
`solution.h`. Preserve this function name and signature exactly:

```cuda
cudaError_t BlackwellGeForceSparseMxfp8Bf16Gemm(
    int M, int N, int K, float alpha,
    __nv_fp8_e4m3 const *A, int lda,
    __nv_fp8_e4m3 const *B, int ldb,
    float beta,
    __nv_bfloat16 const *C, int ldc,
    __nv_bfloat16 *D, int ldd);
```

Do not replace it with `BlackwellGeForceSparseMxfp8Gemm` or any other guessed
name. The target file entrypoint is authoritative.

## Data Contract

- `A` is a decompressed FP8 E4M3 row-major matrix with shape `[M, K]`.
- `A` contains the 2:4 sparse values after decompression; sparse metadata and
  compressed A are not passed to the solution entrypoint.
- `B` is FP8 E4M3 column-major with shape `[K, N]` and leading dimension `ldb=K`.
- `C` is BF16 row-major `[M, N]`.
- `D` is BF16 row-major `[M, N]`.
- The operation is `D = alpha * A * B + beta * C`.

The CUTLASS reference path still uses the SM120 sparse/block-scaled GEMM
internally. The solution path is only given the visible `A`, `B`, `C`, and `D`
pointers above, and correctness is checked against the CUTLASS reference output.

## Benchmark Sizes

KAI runs the benchmark with:

- `M=N=K=512`
- `M=N=K=1024`
- `M=N=K=2048`

The harness prints `Kernel time: <ms>` for the solution path and `Ref time:
<ms>` for the CUTLASS reference path.

## Optimization Notes

This is an SM120 hardware-aware optimization task. SM120-specific Tensor Core
knowledge is useful, but the visible solution API does not expose compressed
sparse metadata or block-scale arrays. Candidate code must not invent hidden
arguments. Do not make sparse Tensor Core instructions a hard requirement unless
the implementation derives all required metadata from visible inputs and keeps a
correct fallback. A dense SM120 FP8/BF16 route, CUTLASS-backed wrapper using
visible arguments, or vectorized CUDA kernel is acceptable if it preserves the
public entrypoint and improves measured `Kernel time`.
