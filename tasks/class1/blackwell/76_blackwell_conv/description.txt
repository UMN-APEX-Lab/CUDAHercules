# Task: 76_blackwell_conv

## Target Hardware
NVIDIA B200 (Blackwell, SM100 / `sm_100a`). The task is built with `-gencode arch=compute_100a,code=sm_100a` and is skipped on other GPUs.

3D convolution forward pass (fprop) in FP16 with FP32 accumulation (implicit GEMM with `tcgen05` / UMMA
tensor cores), compared against the CUTLASS 3.x Blackwell implicit-GEMM convolution (example 76).
The layers are real 3D layers (temporal extent T > 1, temporal padding and stride) of a causal video VAE,
plus the 3x3 layers of ResNet-50 at batch 256 (2D convolutions, D = T = 1).

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_fp16.h>

cudaError_t BlackwellConv3dFprop(
    int N, int D, int H, int W, int C,
    int K, int T, int R, int S,
    int pad_d, int pad_h, int pad_w,
    int stride_d, int stride_h, int stride_w,
    __half const *input, __half const *filter, __half *output);
```

## Operation

With Z = (D + 2*pad_d - T) / stride_d + 1, P = (H + 2*pad_h - R) / stride_h + 1,
Q = (W + 2*pad_w - S) / stride_w + 1 (zero padding, dilation 1, no bias, no activation):

    output[n,z,p,q,k] = sum_{t,r,s,c} input[n, z*stride_d + t - pad_d, p*stride_h + r - pad_h, q*stride_w + s - pad_w, c]
                                      * filter[k,t,r,s,c]

Input positions outside [0,D) x [0,H) x [0,W) contribute zero. This is cross-correlation (the filter is
**not** flipped), as in every deep-learning framework. The temporal dimension is a real dimension: the
filter has T taps along D, the temporal padding and stride are applied exactly like the spatial ones.

## Data Types and Precision

input, filter and output are FP16. Products must be accumulated in FP32 and rounded to FP16 once, at the
end. Lower-precision arithmetic (FP8, FP6, FP4, INT8, BF16, or FP16 accumulation, including tensor-core
paths that use them) is not allowed even if it were to pass the tolerance.

## Memory Layout

- input:  NDHWC `[N, D, H, W, C]`, element (n,d,h,w,c) at `((((n*D + d)*H + h)*W + w)*C + c)`.
- filter: KTRSC `[K, T, R, S, C]`, element (k,t,r,s,c) at `((((k*T + t)*R + r)*S + s)*C + c)`.
- output: NDHWC `[N, Z, P, Q, K]`.

C and K are multiples of 32. All pointers are device pointers, 256-byte aligned. The output buffer holds
NaN on entry: every element must be written.

## Correctness

The CUTLASS reference and your solution write to separate buffers that are pre-filled with NaN.
After your function returns, **every** output element is compared with the reference:

- every element must be finite (NaN / Inf fail, so unwritten elements fail);
- `|out - ref| <= 1e-2 * RMS(ref) + |ref| / 1024` for every element (the second term is one FP16 ulp, so a
  last-bit difference in the FP16 rounding is accepted);
- the relative Frobenius error `||out - ref|| / ||ref||` must be `<= 4e-4`.

The Frobenius bound is about 4.7x above the error of a plain FP32-accumulating kernel (8.6e-5, which is
pure FP16 output rounding) and about 5.7x below the error of a kernel that rounds the inputs to BF16
(2.3e-3); FP16 accumulation gives 3.5e-3 .. 1.4e-2, FP8 inputs 3.6e-2. Solutions that ignore the temporal
extent or the temporal padding / stride, use the wrong spatial padding / stride, replicate instead of
zero-padding, flip the filter, or skip part of the reduction fail on the layers they affect. The check is
repeated once more after the timing loop, from a freshly poisoned output.

**The input tensor changes on every call.** As in deployment, the input activations are regenerated with a new
random seed outside the timed region before every timed call of the reference and of your function, and the
post-timing re-check uses yet another fresh input (the reference output is recomputed for it). The output
and any input-dependent intermediate must therefore be recomputed on every call; a solution that caches its
result between calls fails the re-check. The filters stay fixed.

## Performance

For each layer the harness times the CUTLASS reference and your function with CUDA events (the L2 cache
is flushed before every trial; the output is re-poisoned outside the timed region) and reports
`Ref time`, `Kernel time` and `Speedup = ref_min / kernel_min`. The score is the geometric mean of the
speedups over the ten layers.

The reference is the CUTLASS sm_100 implicit-GEMM convolution (TMA im2col loads, UMMA) with a tile /
cluster configuration chosen per layer from a sweep of 11 configurations on B200 (2-SM 256x128 or 256x256
tiles with 2x1 clusters, a 4x1 cluster for the 8x decoder layer). It reaches 90-113% of cuDNN
(torch `conv3d`, channels-last-3d, FP16) on every layer (about 1.2-1.7 PFLOP/s).

Your function is timed as a whole call, including any host-side launch setup. One-time setup (e.g.
`cudaFuncSetAttribute`, tensor-map creation) may be cached in function-local statics.

## Rules

- Solutions must be your own kernels: no cuBLAS / cuDNN, and no CUTLASS device / kernel / collective
  conv / GEMM templates. CuTe and low-level building blocks (barriers, pipelines, layouts, `tcgen05` PTX)
  are allowed.
- Only the forward pass is tested (no dgrad / wgrad).
