# Task: 70_blackwell_fp8_gemm

## Target Hardware
NVIDIA B200 (Blackwell, SM100 / `sm_100a`). The task is built with `-gencode arch=compute_100a,code=sm_100a`; on any other GPU the test exits with an error (it never reports a pass without running).

FP8 (E4M3) General Matrix Multiply with BF16 output (tcgen05 / UMMA tensor-core GEMM), compared against a CUTLASS 3.x Blackwell FP8 GEMM.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_fp8.h>
#include <cuda_bf16.h>

cudaError_t BlackwellFp8Gemm(
    int M, int N, int K,
    float alpha,
    __nv_fp8_e4m3 const *A, int lda,
    __nv_fp8_e4m3 const *B, int ldb,
    float beta,
    __nv_bfloat16 *C, int ldc);
```

## Operation

C = alpha * A * B + beta * C

A is M x K, B is K x N, C is M x N. There is no bias, activation, auxiliary output or amax: the
reference computes exactly this operation.

## Data Types and Precision

A and B are FP8 E4M3, C is BF16. Products must be accumulated in FP32 and rounded to BF16 only
once, at the end (`alpha * acc + beta * C`). Lower-precision arithmetic (FP4, FP6, E5M2, INT8, FP16
or BF16 accumulation, including tensor-core paths that use them) is not allowed even if it were
to pass the tolerance.

## Memory Layout

- A: **row-major** [M, K]. Element (i, k) at `A[i * lda + k]`, `lda == K`.
- B: **column-major** [K, N] (equivalently row-major [N, K]). Element (k, j) at `B[k + j * ldb]`, `ldb == K`.
- C: **row-major** [M, N]. Element (i, j) at `C[i * ldc + j]`, `ldc == N`.

All pointers are device pointers, 256-byte aligned. When `beta == 0`, C holds NaN on entry:
you must not read it (do not compute `0 * C`).

## Build & Test

```bash

./test                       # runs every benchmark shape below
./test 8192 8192 8192        # one custom shape: M N K
```

`make ref` builds the CUTLASS reference alone.

## Problem Sizes

The linear layers of Llama-3-70B in FP8 on one B200 (hidden 8192, 64 query / 8 KV heads of
dimension 128 -> fused QKV 10240, FFN 28672 -> fused gate+up 57344, vocabulary 128256).
M is the number of tokens: a prefill chunk of 8K / 16K tokens, or one decode step of 128
concurrent sequences.

| label             | M     | N      | K     | layer                         |
|-------------------|-------|--------|-------|-------------------------------|
| decode_qkv        | 128   | 10240  | 8192  | fused QKV projection          |
| decode_mlp_down   | 128   | 8192   | 28672 | FFN down projection           |
| decode_lm_head    | 128   | 128256 | 8192  | LM head                       |
| prefill_qkv       | 8192  | 10240  | 8192  | fused QKV projection          |
| prefill_o_proj    | 8192  | 8192   | 8192  | attention output projection   |
| prefill_mlp_up    | 8192  | 57344  | 8192  | fused gate+up projection      |
| prefill_mlp_down  | 8192  | 8192   | 28672 | FFN down projection           |
| prefill16k_o_proj | 16384 | 8192   | 8192  | output projection, 16K chunk  |

All shapes use `alpha = 1, beta = 0`. One extra correctness-only case (M=384, N=1280, K=2048,
`alpha = 0.75`, `beta = 0.5`, C initialised with random BF16 data) checks the alpha / beta
handling; it is not timed. A and B hold uniform random values in [-1, 1) rounded to E4M3 (random
mantissas and exponents, no structure).

## Correctness

The CUTLASS reference and your solution write to separate buffers that are pre-filled with NaN.
After your function returns, **every** element of C is compared with the reference output:

- every element must be finite (NaN / Inf fail, so unwritten elements fail);
- `|C - ref| <= 1e-3 * RMS(ref) + 1.6e-2 * |ref|` for every element (the second term allows a
  difference of one BF16 rounding step), and the relative Frobenius error
  `||C - ref|| / ||ref||` must be `<= 2e-4`.

FP8 products are exact in FP32, so a correct kernel differs from the reference by a relative
Frobenius error of about 3e-5 at most (BF16 rounding flips). The bound is about 6x above that, and
more than 60x below the error of FP16-accumulating (1.3e-2), E5M2-input (8e-2) or FP4-input (4e-1)
kernels. The check is repeated once more after the timing loop, with a fresh A and a freshly poisoned C.

**Inputs change on every call.** The activation matrix A is regenerated with a new random seed before every timed call of both the
reference and your function (outside the timed region, before the L2 flush), so outputs and any
input-dependent intermediate must be recomputed on every call; memoizing results does not work. After the timing loop
the harness regenerates the input once more, recomputes the reference for it, re-poisons the output and calls your
function again; that second check must pass too. The second operand B (the weights) stays fixed, and one-time
preprocessing of B (and its scales) into a function-local static cache keyed on the pointers and the shape is allowed, as
is other one-time setup (see "Performance").

## Performance

For each shape the harness times the CUTLASS reference and your function with CUDA events (the L2
cache is flushed before every trial; C is re-poisoned outside the timed region) and reports
`Ref time`, `Kernel time` and `Speedup = ref_min / kernel_min` (minimum over the same number of
trials for both). The score is the geometric mean of the speedups over the eight shapes.
The reference uses a tile / cluster configuration chosen per shape from a sweep on B200 (prefill:
256x256x128 tile with a 2x1 cluster; decode: 128x128x128 with a 2x1 cluster). It reaches
81-120% of cuBLAS FP8 (`torch._scaled_mm`, same shapes, BF16 out) on every shape, 3.0 PFLOPs on the large
prefill GEMMs.

Your function is timed as a whole call, including any host-side launch setup. One-time setup
(e.g. `cudaFuncSetAttribute`, tensor-map creation) may be cached in function-local statics.

## Rules

- Solutions must be your own kernels: no cuBLAS / cuDNN, and no CUTLASS device / kernel / collective
  GEMM templates. CuTe and low-level building blocks (barriers, pipelines, layouts, `tcgen05` PTX) are
  allowed.
- FP8 E4M3 operands with FP32 accumulation only (see "Data Types and Precision").
