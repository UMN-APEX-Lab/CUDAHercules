# Task: tk_nvfp4_gemm

## Target Hardware
NVIDIA B200 (Blackwell, SM100 / `sm_100a`). The task is built with `-gencode arch=compute_100a,code=sm_100a`.

NVFP4 (NVIDIA 4-bit floating point) two-level block-scaled GEMM with BF16 output (tcgen05 block-scaled MMA),
compared against the ThunderKittens Blackwell NVFP4 GEMM.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_bf16.h>
#include <cuda_fp8.h>
#include <cuda_fp4.h>

void Nvfp4Gemm(
    __nv_fp4x2_e2m1 *A, __nv_fp4x2_e2m1 *B,
    __nv_fp8_e4m3 *A_scale, __nv_fp8_e4m3 *B_scale,
    float *A_scale_global, float *B_scale_global,
    __nv_bfloat16 *C, int M, int N, int K);
```

## Operation

C = A_scale_global * B_scale_global * (A * sA) * (B * sB)^T

A is M x K, B is N x K (stored transposed), C is M x N; C is row-major BF16 (`C[i * N + j]`). A and B hold FP4 E2M1
values packed two per byte: row i occupies K/2 contiguous bytes (`A + i * K / 2`), element k is in byte k / 2, the
**low nibble for even k, the high nibble for odd k**. E2M1: bit 3 is the sign, bits 2..0 select the magnitude
{0, 0.5, 1, 1.5, 2, 3, 4, 6}. sA / sB hold one **E4M3** scale per **16 consecutive K elements** of a row:
element (i, k) of A is dequantized as `e2m1(A[i, k]) * float(sA[i, k / 16])`, likewise for B.
`A_scale_global` and `B_scale_global` are single FP32 values in device memory (the per-tensor scales).

## Scale layout (swizzled 128x4 tiles, the layout tcgen05 and cuBLAS consume)

The scales of 128 rows x 4 K-blocks (= 128 rows x 64 K elements) form one 512-byte tile; tiles are ordered
row-block major, K-group minor. The scale of (row r, K-block kb = k / 16) of A (or of B, with its row = output column) is at byte

    index = ((r / 128) * (K / 64) + kb / 4) * 512 + (r % 32) * 16 + ((r / 32) % 4) * 4 + (kb % 4)

so `A_scale` has M * K / 16 bytes and `B_scale` N * K / 16 bytes.

## Data Types and Precision

A, B: FP4 E2M1 with E4M3 block scales and FP32 global scales. Output: BF16. Products must be accumulated in
FP32 and rounded to BF16 once, at the end (FP4 x E4M3-scale products are exact in FP32). FP16 or BF16 accumulation
(including tensor-core paths that use them) and approximating the block scales (e.g. as powers of two) are not
allowed even if they were to pass the tolerance.

All pointers are device pointers, 256-byte aligned. C holds NaN on entry: you must overwrite every element.
M and N are multiples of 256, K a multiple of 256 (all tested shapes satisfy this).

## Problem Sizes

The linear layers of Llama-3-70B in NVFP4 on one B200 (hidden 8192, fused QKV 10240, FFN 28672 -> fused gate+up
57344). M is the number of tokens: a 256-token batch, or an 8K / 16K-token prefill chunk.

| label                    | M     | N     | K     | layer                        |
|--------------------------|-------|-------|-------|------------------------------|
| decode_batch256_qkv      | 256   | 10240 | 8192  | fused QKV projection         |
| decode_batch256_mlp_down | 256   | 8192  | 28672 | FFN down projection          |
| prefill_qkv              | 8192  | 10240 | 8192  | fused QKV projection         |
| prefill_o_proj           | 8192  | 8192  | 8192  | attention output projection  |
| prefill_mlp_up           | 8192  | 57344 | 8192  | fused gate+up projection     |
| prefill_mlp_down         | 8192  | 8192  | 28672 | FFN down projection          |
| prefill16k_o_proj        | 16384 | 8192  | 8192  | output projection, 16K chunk |

The FP4 operands are random bytes (all 16 codes occur); block scales are random E4M3 values in [0.25, 4); the
global scales are random positive floats in [0.5, 2).

## Correctness

The reference and your solution write to separate buffers that are pre-filled with NaN. After your
function returns, **every** element of C is compared with the reference output:

- every element must be finite (NaN / Inf fail, so unwritten elements fail);
- `|C - ref| <= 1e-3 * RMS(ref) + 1.6e-2 * |ref|` for every element (the second term allows two BF16
  rounding steps), and the relative Frobenius error `||C - ref|| / ||ref||` must be `<= 2e-4`.

**Inputs change on every call.** The activation matrix A together with its E4M3 block scales and its
global scale is regenerated with a new random seed before every timed call of both the reference and
your function (outside the timed region), so outputs and any input-dependent intermediate must be
recomputed on every call; memoizing results does not work. After the timing loop the harness
regenerates A, its block scales and its global scale once more, recomputes the reference, re-poisons
the output and calls your function again; that final check on fresh inputs must pass too (it runs for
every shape). The weights B, their block scales and their global scale stay fixed, and one-time
preprocessing of B and its scales into a function-local static cache keyed on the pointers and the
shape is allowed.

## Performance

For each shape the harness times the reference and your function with CUDA events (the L2 cache is
flushed before every trial; C is re-poisoned outside the timed region) and reports `Ref time`,
`Kernel time` and `Speedup = ref_min / kernel_min`. The score is the geometric mean of the speedups
over the seven shapes.

Your function is timed as a whole call, including any host-side launch setup. One-time setup (e.g.
`cudaFuncSetAttribute`, tensor-map creation) may be cached in function-local statics. The shipped
`solution.h` is a simple correct baseline that you may replace entirely.

## Rules

- Solutions must be your own kernels: no ThunderKittens (`kittens::` / its headers are rejected), no cuBLAS / cuDNN, and
  no CUTLASS device / kernel / collective GEMM templates. CuTe and low-level building blocks (barriers, `tcgen05`
  PTX, TMA) are allowed.
- FP4 operands with E4M3 block scales, FP32 global scales and FP32 accumulation only (see "Data Types and Precision").
