# Task: 21_quaternion_gemm

Quaternion General Matrix Multiply (QGEMM).

A quaternion q = w + x*i + y*j + z*k is stored as 4 consecutive floats in order (x, y, z, w).
Quaternion multiplication uses the Hamilton product:
  result.x = a.w*b.x + b.w*a.x + a.y*b.z - a.z*b.y
  result.y = a.w*b.y + b.w*a.y + a.z*b.x - a.x*b.z
  result.z = a.w*b.z + b.w*a.z + a.x*b.y - a.y*b.x
  result.w = a.w*b.w - a.x*b.x - a.y*b.y - a.z*b.z

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>

cudaError_t QuaternionGemm(
    int M, int N, int K,
    float alpha,
    float const *A, int lda,
    float const *B, int ldb,
    float beta,
    float *C, int ldc);
```

## Operation

C = alpha * A * B + beta * C

Where:
- A is M x K quaternions (row-major)
- B is K x N quaternions (column-major)
- C is M x N quaternions (row-major)
- Multiplication between quaternion elements uses the Hamilton product
- alpha and beta are real scalars applied component-wise to the quaternion result

## Data Types and Precision

All data is `float` (FP32). Each quaternion element occupies 4 consecutive floats in order
(x, y, z, w).

The result must be FP32-accurate: it is checked against an FP64 reference with the tolerance
below, which single-pass lower-precision computation cannot meet. How FP32 accuracy is reached is
up to you: native FP32 arithmetic, or emulating FP32 with lower-precision units (e.g. 3xTF32 or
multi-term BF16 splitting on tensor cores), are both allowed as long as the result meets the
tolerance.

## Memory Layout

- A: **Row-major**. Quaternion (i,k) starts at `A[(i * lda + k) * 4]`.  lda >= K.
- B: **Column-major**. Quaternion (k,j) starts at `B[(k + j * ldb) * 4]`.  ldb >= K.
- C: **Row-major**. Quaternion (i,j) starts at `C[(i * ldc + j) * 4]`.  ldc >= N.

## Problem Sizes

Quaternion-valued versions of the Qwen3-32B linear layers served on one GPU (real dimensions
divided by 4: hidden 5120 -> 1280, fused QKV 10240 -> 2560, attention output 8192 -> 2048,
FFN 25600 -> 6400); M = tokens, either a 16K-token prefill chunk or one decode step of 128
concurrent sequences; sizes in quaternions:

| label            | M     | N     | K    | layer                                  |
|------------------|-------|-------|------|----------------------------------------|
| decode_qkv       | 128   | 2560  | 1280 | fused QKV projection, decode           |
| prefill_qkv      | 16384 | 2560  | 1280 | fused QKV projection, prefill          |
| prefill_o_proj   | 16384 | 1280  | 2048 | attention output projection, prefill   |
| prefill_mlp_up   | 16384 | 12800 | 1280 | fused gate+up projection, prefill      |
| prefill_mlp_down | 16384 | 1280  | 6400 | down projection, prefill               |

alpha = 1, beta = 0, lda = K, ldb = K, ldc = N. With beta = 0 the initial contents of C are
arbitrary finite values that must not affect the result.

## Correctness

Inputs are random FP32 values in [-1, 1) that use the full 24-bit significand. Every component
of C is compared with the exact (FP64-accumulated) result:
- every component must be finite and satisfy |C - exact| <= 1.5e-6 * sqrt(4K) * RMS(exact);
- the relative Frobenius error ||C - exact|| / ||exact|| must be <= 5.5e-8 * sqrt(4K).
Components that are not written fail the check.

Performance is timed for both the reference and your solution at each size; the task score is
the geometric mean of the per-size speedups.

CUTLASS headers are available on the include path.
