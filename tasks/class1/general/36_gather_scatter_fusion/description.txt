# Task: 36_gather_scatter_fusion

Gather-Scatter GEMM (FP16 inputs, FP32 accumulation and output): a GEMM whose input rows are
gathered and whose output rows are scattered through index arrays, as in Mixture-of-Experts
token dispatch for one expert.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_fp16.h>

cudaError_t GatherScatterGemm(
    int M, int N, int K, float alpha,
    __half const *A, int lda, int const *gather_A,
    __half const *B, int ldb,
    float beta,
    float const *C, int ldc, int const *gather_C,
    float *D, int ldd, int const *scatter_D);
```

## Operation

For i = 0..M-1 and j = 0..N-1:

D[scatter_D[i], j] = alpha * sum_{k=0..K-1} A[gather_A[i], k] * B[k, j] + beta * C[gather_C[i], j]

Where:
- A is a backing store of A_rows x K (only the M rows listed in gather_A are used)
- B is K x N
- C and D are D_rows x N; only the M rows of D listed in scatter_D may be written,
  all other rows of D must be left unchanged
- gather_A, gather_C, scatter_D are device arrays of length M; entries of scatter_D are distinct

## Data Types and Precision

- A, B: `__half` (FP16)
- C, D: `float` (FP32)

Products of the FP16 inputs must be accumulated in FP32 and written as FP32. Lower-precision
arithmetic (FP16/BF16 accumulation or output rounding, FP8 or INT8 operands) is not allowed even
if it passes the tolerance.

## Memory Layout

All matrices are **row-major**:
- A: Element (r,k) at `A[r * lda + k]`. lda >= K.
- B: Element (k,j) at `B[k * ldb + j]`. ldb >= N.
- C: Element (r,j) at `C[r * ldc + j]`. ldc >= N.
- D: Element (r,j) at `D[r * ldd + j]`. ldd >= N.

## Problem Sizes

The gate+up projection of one MoE expert during a 16K-token prefill chunk on one GPU. The
A_rows = 16384 tokens are routed with top-k gating; the expert receives M distinct tokens
(about A_rows * top_k / experts; gather_A, in token order), and each result row is written to
that token's (token, k) slot of an [A_rows * top_k, N] output buffer (scatter_D;
gather_C == scatter_D). K = hidden size, N = per-GPU gate+up width. lda = K, ldb = ldc = ldd = N.

| label            | M    | N     | K    | top_k | model / deployment                                        |
|------------------|------|-------|------|-------|-----------------------------------------------------------|
| qwen3_30b_a3b    | 1024 | 1536  | 2048 | 8     | Qwen3-30B-A3B (128 experts, expert FFN 768), single GPU    |
| deepseek_v2_lite | 1536 | 2816  | 2048 | 6     | DeepSeek-V2-Lite (64 experts, expert FFN 1408), single GPU |
| mixtral_8x7b_tp2 | 4096 | 14336 | 4096 | 2     | Mixtral-8x7B (8 experts), tensor-parallel-2 shard          |
| deepseek_v3_ep   | 512  | 4096  | 7168 | 8     | DeepSeek-V3 (256 experts, expert FFN 2048), expert parallel |

alpha = 1, beta = 0.

## Correctness

Inputs are random values in [-1, 1) using the full significand of their type (FP16 for A and B,
FP32 for C). D is pre-filled with a sentinel value; every element of the whole D buffer is
checked:
- rows listed in scatter_D: every element finite and |D - exact| <= 2e-6 * sqrt(K) * RMS(exact),
  and the relative Frobenius error over these rows <= 3e-7 * sqrt(K), against the exact
  (FP64-accumulated) result;
- all other rows must be left bit-for-bit unchanged.

Performance is timed for both the reference and your solution at each size; the task score is
the geometric mean of the per-size speedups.

CUTLASS headers are available on the include path.
