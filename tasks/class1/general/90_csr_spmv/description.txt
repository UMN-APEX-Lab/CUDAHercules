# Task: 90_csr_spmv

Sparse matrix-vector multiplication y = A x for large FP32 CSR matrices.

## Function Signatures

Implement the following three functions in `solution.h` (C++ linkage):

```cuda
#pragma once
#include <cuda_runtime.h>

// NOT timed. Receives only the matrix A. May convert A to any storage format and build any
// auxiliary data over A (device or host memory); returns an opaque context.
void* spmv_preprocess(const int* d_row_ptr, const int* d_col_ind, const float* d_values,
                      int num_rows, int num_cols, int nnz);

// The ONLY timed function: y = A x.
void spmv_compute(void* ctx,
                  const int* d_row_ptr, const int* d_col_ind, const float* d_values,
                  const float* d_x, float* d_y,
                  int num_rows, int num_cols, int nnz);

// Releases everything spmv_preprocess and spmv_compute allocated.
void spmv_cleanup(void* ctx);
```

All pointers are device pointers. A is in CSR format with 0-based, sorted column indices:
row r holds the entries `d_values[j]` at columns `d_col_ind[j]` for
`d_row_ptr[r] <= j < d_row_ptr[r + 1]`. `d_x` has `num_cols` entries, `d_y` has `num_rows`.

## Calling Protocol

For every test matrix: `spmv_preprocess` is called once, then `spmv_compute` is called many times
with the same A and the same buffers, then `spmv_cleanup`. Between calls, x changes (two different
input vectors alternate) and y is zero-filled; both happen outside the timed region, so partial sums
may be accumulated into y. Each call must compute y from the x it receives: results must not be
carried over from one call to the next. `spmv_compute` may launch work on any stream; the timing
covers everything until the device is idle.

## Correctness

x holds random FP32 values in [-1, 1). Every element of y is compared with the FP64-accumulated
product: an element matches if it is finite and its absolute error is at most 0.01 or its relative
error |y - exact| / (|exact| + 1e-8) is at most 0.01. A result is correct if at most 0.1% of the
elements mismatch. The check runs on the first call and on every timed call. The mismatch allowance
exists for rounding differences only; skipping part of the computation is reward hacking.

Internal arithmetic precision is up to you as long as every result passes this check.

## Performance

For every matrix, a tuned reference implementation and your solution are timed with the same
protocol (L2 flushed before every call, minimum over the timed calls); the task score is the
geometric mean of the per-matrix speedups.

## Rules

- Write your own kernels in CUDA C++. Do not call cuSPARSE, cuBLAS, cuSOLVER or any other library
  routine that computes the operation; CUB and Thrust primitives (scan, sort, ...) are allowed.
- `spmv_preprocess` may only reorganize A; it must not compute anything that depends on x.
