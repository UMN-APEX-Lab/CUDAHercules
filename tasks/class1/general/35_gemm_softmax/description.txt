# Task: 35_gemm_softmax

Batched GEMM + row-wise Softmax on half-precision (FP16) data.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>
#include <cuda_fp16.h>

cudaError_t gemm_softmax_solution(
    int M, int N, int K,
    float alpha, float beta,
    __half const *A, int lda,
    __half const *B, int ldb,
    __half const *C, int ldc,
    __half *D, int ldd,
    __half *Softmax, int lds,
    int batch_count,
    int64_t batch_stride_A,
    int64_t batch_stride_B,
    int64_t batch_stride_C,
    int64_t batch_stride_D,
    int64_t batch_stride_Softmax);
```

## Operation

For each batch b = 0 .. batch_count-1:
  1. GEMM:     D[m,n] = alpha * sum_k(A[m,k] * B[k,n]) + beta * C[m,n]
  2. Softmax:  Softmax[m,n] = exp(D[m,n] - max_n(D[m,:])) / sum_n(exp(D[m,n'] - max_n(D[m,:])))

Row-wise softmax: each row m is independently normalized across columns n=0..N-1. Both D and
Softmax are outputs.

## Data Types and Precision

All matrices are `__half` (FP16); alpha and beta are `float`. The GEMM must accumulate in FP32
and the softmax must be computed in FP32 arithmetic (from the FP32 or the FP16-rounded logits).
Lower-precision arithmetic (FP16 accumulation, BF16, FP8, INT8 or narrower formats) is not
allowed, even if it passes the tolerance.

## Memory Layouts

- A: **row-major**, shape [M, K].  Element (m,k) at `A[m * lda + k]`.  lda >= K.
- B: **column-major**, shape [K, N].  Element (k,n) at `B[k + n * ldb]`.  ldb >= K.
- C, D, Softmax: **row-major**, shape [M, N].  Element (m,n) at `X[m * ldx + n]`.  ldx >= N.

The test uses packed matrices (lda = ldb = K, ldc = ldd = lds = N).

## Batching

`batch_count` independent problems. For batch b, offset each pointer by:
  A_b = A + b * batch_stride_A
  B_b = B + b * batch_stride_B
  (same for C, D, Softmax with their respective batch strides)

## Problem Sizes

alpha = 1/sqrt(K) at every size; shapes as run on a single 96 GB GPU:

| name              | M     | N      | K    | batch | beta | workload                                                        |
|-------------------|-------|--------|------|-------|------|-----------------------------------------------------------------|
| attn_prefill_d64  | 512   | 512    | 64   | 1024  | 1    | BERT-large training attention scores, 64 seqs x 16 heads        |
| attn_prefill_d128 | 4096  | 4096   | 128  | 64    | 1    | Qwen3-32B attention scores, 64 heads, 4K-token prompt           |
| attn_prefill_d256 | 8192  | 8192   | 256  | 16    | 1    | Gemma-2-9B attention scores, 16 heads x 256, 8K-token prompt    |
| attn_decode_gqa   | 8     | 6144   | 128  | 128   | 1    | Qwen3-32B decode scores, 16 seqs x 8 KV heads, 6K context       |
| lm_head_softmax   | 128   | 262208 | 5376 | 1     | 0    | Gemma-3-27B LM head + softmax over the 262K vocabulary          |
| moe_router        | 16384 | 128    | 2048 | 1     | 0    | Qwen3-30B-A3B MoE router over 128 experts, 16K-token chunk      |

(beta = 1: C is an additive attention bias/mask.)

## Correctness

Two input sets are used, and they alternate between consecutive calls:
- set 0: A, B, C random FP16 values uniform in [-2, 2);
- set 1 (attention-like): logits alpha * A.B with a standard deviation of about 4, plus one "sink"
  column per batch (like a BOS token) whose logit is about +16 for every row; C uniform in [-1, 1).

Both outputs are compared on every element with an FP32 reference (FP32-accumulated GEMM; softmax s
of the FP32 logits g):
- D:       |D - ref| <= 1e-3 + 2e-3 * |ref|
- Softmax: |S - s| <= 1e-6 + |s| * (3e-3 + 2.5 * (h(g) + H)), and every Softmax row must sum to 1
  within 5e-4 + H, where h(v) is half an FP16 ulp at |v| and H = sum_j s_j * h(g_j) over the row
  (this allows for a softmax computed from the FP16-rounded D)
Every element must be written and finite. The solution is verified before timing, after every timed
call (inputs restored and outputs re-poisoned before each call) and again after the timed runs.

## Build & Test

```bash
make test                             # requires solution.h in task directory
./test                                # default: runs all problem sizes listed above
./test --m=1024 --n=512 --k=256 --batch_count=8 [--beta=1]   # custom single size (N, K multiples of 8)
./test --iterations=50                # more profiling iterations (default: 20)
```

Performance is timed for both the reference and your solution at each size; the task speedup is
the geometric mean of the per-size speedups.

CUTLASS headers are available on the include path.
