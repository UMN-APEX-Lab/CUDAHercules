# Task: 29_ampere_3xtf32_fast_accurate_tensorop_complex_gemm

Complex float GEMM with 3xTF32 accuracy. A is column-major, B/C/D are row-major.
Complex numbers stored as interleaved (real, imag) float pairs.

## Function Signature

Implement the following function in `solution.h`:

```cuda
#pragma once
#include <cuda_runtime.h>

cudaError_t ComplexGemm(
    int M, int N, int K,
    float alpha_real, float alpha_imag,
    float const *A, int lda,
    float const *B, int ldb,
    float beta_real, float beta_imag,
    float const *C, int ldc,
    float *D, int ldd);
```

## Operation

D = alpha * A * B + beta * C  (complex arithmetic)

Where:
- A is M x K (column-major complex)
- B is K x N (row-major complex)
- C is M x N (row-major complex)
- D is M x N (row-major complex)

## Data Types and Precision

All matrices use `float` pairs for complex numbers. Each complex element occupies 2 consecutive
floats: (real, imaginary).

The result must have FP32-level accuracy: FP32 arithmetic, or an error-compensated tensor-core
scheme with equivalent accuracy such as 3xTF32 (operands split into high and low TF32 parts).
Single-pass TF32, FP16, BF16, FP8 or INT8 arithmetic is not allowed even if it passes the
tolerance.

## Memory Layout

Complex numbers are stored as interleaved (real, imag) pairs.
lda/ldb/ldc/ldd are in units of complex elements (not floats).

- A (column-major): Element (i,k) at `A[(i + k*lda)*2]` (real), `A[(i + k*lda)*2+1]` (imag). lda >= M.
- B (row-major): Element (k,j) at `B[(k*ldb + j)*2]` (real), `B[(k*ldb + j)*2+1]` (imag). ldb >= N.
- C (row-major): Element (i,j) at `C[(i*ldc + j)*2]` (real), `C[(i*ldc + j)*2+1]` (imag). ldc >= N.
- D (row-major): Element (i,j) at `D[(i*ldd + j)*2]` (real), `D[(i*ldd + j)*2+1]` (imag). ldd >= N.

alpha = 1 + 0i, beta = 0, lda = M, ldb = ldc = ldd = N.

## Correctness

Inputs are random complex values whose real and imaginary parts are FP32 values in [-1, 1)
using the full 24-bit significand. D is filled with NaN before your function runs, so elements
that are not written fail. Every real and imaginary component of D is compared with the exact
(FP64-accumulated) result:
- every component must be finite and satisfy |D - exact| <= 1.5e-6 * sqrt(2K) * RMS(exact);
- the relative Frobenius error ||D - exact|| / ||exact|| must be <= 1.2e-7 * sqrt(2K).

Performance is timed for both the reference and your solution at each size; the task score is
the geometric mean of the per-size speedups.

CUTLASS headers are available on the include path.
